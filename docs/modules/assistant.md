# AI 智能助手 模块开发需求模板

## 1. 模块定位
- 助手服务对象：主要为B端用户，包括 维修厂采购员、汽修技师、门店顾问、批发商采购人员。
- 不是一个独立聊天产品，而是系统中的业务执行型助手。它应具备以下定位：
    1. 识别用户需求：快速智能识别用户需求，识别出业务后续步骤。
    2. 定型助手：结合VIN和车型参数给出车型信息。
    3. 适配助手：找出适配车型的配件并列出配件列表
    4. 交易助手：支持加入购物车、组合推荐、替代件推荐
    5. 历史会话：可以从历史会话中继续聊天


## 2. 入口与唤起方式
- 全局入口位置：
    1. 位于系统框架上的按钮，点击后可以在系统全局中打开智能助手弹窗。
    2. 弹出时不需要页面遮罩，智能助手弹窗外加阴影，与主系统在视觉上有区分即可。


## 3. 能力范围
- 需求识别：用户进入时或发起新对话时，向用户获取当前对话主要目标。比如：配件订购、订单查询、车辆维修建议、事故车定损、其他
- EPC查询：通过用户的车型文字描述或上传的VIN码图片，给出车型信息，用户确认后系统跳转至EPC对应的页面
- 配件订购协助：通过用户的车型文字描述或上传的VIN码图片、配件清单，给出配件清单数据。询问用户意向后选择购物车、直接生成询价单或订单。
- 订单查询协助：通过用户对订单的文字描述（订单生成时间、订单备注、车型信息等），给出符合需求的订单，通过点击订单后主系统跳转至对应的订单详情。
- 车辆碰撞分析协助：通过用户上传的VIN码图片、车辆碰撞图（可能多张），给出事故评定、维修换件建议、初步定损报告。
- 其他：通过用户的描述，识别用户的需求。
- 对话历史：以车型或VIN作为对话分区，保证聊天内容互相不干涉。

## 4. 对话体验
- 卡片式确认交互：智能助手给出的回答以卡片的形式呈现；向用户获取的信息时，用户输入或上传后，以卡片的形式给出确认信息，用户确认后执行查询操作。
- 首次打开展示内容：您好，欢迎使用S-Link智能助手，请在下方卡片中选择你的业务需求。
- 功能规则：需求识别 -> 要求用户输入信息 -> 分析输入信息 -> 判断是否需要用户补充信息 -> 整理信息后查询系统 -> 生成结果 -> 确认用户是否有补充
- 失败兜底文案：您好，当前无法判断您的需求，您可以前往对应系统手动操作。

## 5. 数据与安全
- 需要的上下文字段：以车型或VIN作为对话分区
- 是否记录会话历史：需要，当用户在对话历史中发起继续聊天，需要参考会话上下文
- 脱敏规则：暂无



## 6. 核心能力需求
### 6.1 对话理解能力
助手需要支持：
- 中文自然语言输入
- 口语化表达理解
- 多轮上下文记忆
- 指代消解（如“这个件”“刚才那个品牌”）
- 纠错与补问
- 用户意图识别

用户意图至少包括：
- 查配件
- 校验适配
- 查价格
- 做品牌对比
- 询问替代件
- 加入购物车
- 查订单
- 查物流
- 转人工

### 6.2 车辆信息识别能力
系统需支持以下车辆信息来源：
- 用户手动输入车型
- 用户手动输入VIN
- 用户上传VIN码图片

系统需支持以下事故车辆信息来源：
- 用户上传事故车图片
- 用户手动输入事故车描述

### 6.3 配件检索能力
系统需支持基于以下方式检索配件：
- 关键词搜索
- 车型限定搜索
- VIN 定向搜索
- OE/OEM 编号搜索
- 故障现象映射搜索

### 6.4 购物车协同能力
能够调用购物车相关功能，支持：
- 添加单个配件到购物车
- 批量添加推荐配件

### 6.4 订单协同能力
能够调用订单生成相关功能，支持：
- 使用VIN、车型信息、配件清单、付款方式、收货信息生成初始待确认订单
- 使用VIN、车型信息、询价区域范围、询价时间生成初始待确认询价单

## 7. 业务流程设计
先提示用户选择或输入需要的业务，根据业务类型系统选择不同的业务流。
### 7.1 EPC查询：通过用户的车型文字描述或上传的VIN码图片，给出车型信息，用户确认后系统跳转至EPC对应的页面
    1. 提示用户输入VIN码，或者上传VIN码图片。（提示语：请输入车辆VIN码或直接将VIN码图片复制粘贴至聊天中。）
    2. 如果上传VIN码图片 -> 系统OCR识别VIN码（当前demo系统没有OCR接口，使用模拟数据向下给出数据）
    3. 通过系统后台接口获取VIN码对应的车辆信息（当前demo系统使用模拟数据给出）
    4. 卡片形式将车型信息给到用户确认（“重新输入”和“确认”按钮）。
    5. 如果用户点击重新输入按钮，则提示用户重新输入，然后从步骤2重复流程。（提示语：请重新输入VIN码。）
    6. 用户确认车型后询问用户需要的配件或图例信息，（提示语：请描述您需要的配件及配件装配的位置，如“汽车前脸”或“装配在前轮的避震器”。）
    7. 理解配件名称及配件装配的位置（使用大模型）
    8. 卡片形式给出EPC中配件所在车型及图例位置，包含跳转按钮和加入购物车按钮。
    9. 询问是否满足用户需求（提示语：您可以直接将配件加入购物车，也可以跳转链接查看图例和装配清单，如未满足您的需求，您可以继续向我描述配件的信息。）
    10. 如果用户继续回复配件相关的内容，则从步骤5重复流程（使用大模型进行理解）
### 7.2 配件订购协助：通过用户的车型文字描述或上传的VIN码图片、配件清单，给出配件清单数据。询问用户意向后选择购物车、直接生成询价单或订单。
    1. 提示用户输入VIN码，或者上传VIN码图片、配件清单图片（可能多张）、配件清单文件（可能多份）。（提示语：请输入车辆VIN码或直接将VIN码图片、配件清单图片或者配件清单文件复制粘贴至聊天中。）
    2. 如果上传VIN码图片 -> 系统OCR识别VIN码（当前demo系统没有OCR接口，使用模拟数据向下给出数据）
    3. 通过系统后台接口获取VIN码对应的车辆信息（当前demo系统使用模拟数据给出）
    4. 卡片形式将车型信息给到用户确认。（“重新输入”和“确认”按钮）（提示语：点击确认后系统开始分析配件清单。）
    5. 如果用户点击重新输入按钮，则提示用户重新输入VIN码，然后从步骤2重复流程。（提示语：请重新输入VIN码。）
    6. 用户确认车型信息后，开始分析配件清单。（使用大模型）（提示语：系统开始分析配件清单，请稍后）
    7. 获取大模型结果后，在卡片中以表格的形式列出清单（VIN、品牌/车系/年款/车型、配件清单表格），配件清单表格包含全选、单选、数量选择器、配件序号、配件号、配件名称。卡片包含加入购物车按钮（点击后加入购物车）、发起询价按钮（待开发）、生成订单按钮（待开发）。
    8. 提示用户可以继续上传配件清单信息，加入配件清单表格中。
    9. 识别出清单数据后（使用大模型），将数据添加至步骤7中生成的配件清单表格中，再次给出结果卡片。
### 7.3 订单查询协助：通过用户对订单的文字描述（订单生成时间、订单备注、车型信息等），给出符合需求的订单，通过点击订单后主系统跳转至对应的订单详情。
    暂缓，待后续功能开发
### 7.4 车辆碰撞分析协助：通过用户上传的VIN码图片、车辆碰撞图（可能多张），给出事故评定及维修建议。
    1. 提示用户输入VIN码，或者上传VIN码图片、车辆碰撞图（可能多张）、输入碰撞描述。（提示语：请输入车辆VIN码或直接将VIN码图片、车辆碰撞图复制粘贴至聊天中，您可以文字补充碰撞描述以丰富分析参数。）
    2. 如果上传VIN码图片 -> 系统OCR识别VIN码（当前demo系统没有OCR接口，使用模拟数据向下给出数据）
    3. 通过系统后台接口获取VIN码对应的车辆信息（当前demo系统使用模拟数据给出）
    4. 卡片形式将车型信息给到用户确认。（“重新输入”和“确认”按钮）（提示语：点击确认后系统开始分析碰撞情况。）
    5. 如果用户点击重新输入按钮，则提示用户重新输入VIN码，然后从步骤2重复流程。（提示语：请重新输入VIN码。）
    6. 用户确认车型信息后，开始使用图片和碰撞描述文字分析碰撞情况。（使用大模型）（提示语：系统开始分析碰撞情况，请稍后）
    7. 获取大模型结果后，在卡片中以表格的形式列出碰撞分析结果（VIN、品牌/车系/年款/车型、碰撞分析结果表格），碰撞分析结果表格包含事故总结、碰撞位置、可见损伤配件、可能损伤配件、需要检查的配件、风险总价、置信度（百分比）。卡片包含“生成换件清单”按钮、“生成初步定损报告”按钮。
    8. 用户点击“生成换件清单”按钮后，将碰撞分析结果表格中的三种配件（可见损伤配件、可能损伤配件、需要检查的配件）全部加入换件清单中生成卡片（VIN、品牌/车系/年款/车型、换件清单表格），换件清单表格包含全选、单选、数量选择器、配件序号、配件号、配件名称、换件建议（更换、建议更换、建议检查），卡片包含加入购物车按钮（点击后加入购物车）、发起询价按钮（待开发）、生成订单按钮（待开发）。
    9. 用户点击“生成初步定损报告”按钮后，按照业内通用定损报告的格式，生成一份初步定损报告。给出卡片，卡片包含在新标签页打开报告的链接。
